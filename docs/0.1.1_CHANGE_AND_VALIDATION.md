# Aurauv 0.1.1 修改与验证审计

- 日期：2026-08-23
- 分支：`master`
- 对比基线：`8c150fa`（Initial public release）
- 目标版本：`0.1.1`
- 状态：实现与验证完成，未创建分支、未提交、未推送

## 1. 结论

本次以 bug fix 范围完成四项修改：

1. 命令日志与 `CommandError` 诊断中的命令派生凭据脱敏；
2. 新增 route-attached `pytorch-companion` provider，使实际安装的
   `torchaudio`、`torchcodec` 等二进制 companion 进入验证闭环与成功 state；
3. 用显式 execution capabilities 约束 `--check`、`--dry-run`、`--locked`、
   `--frozen`，禁止 Aurauv 自身追加 update/install/repair/resync/state 写入；
4. 为 `add/remove` 增加内存 metadata checkpoint、失败恢复、可证明时的环境补偿
   同步，并收紧 provider membership/order 合同。

最终完整测试结果为 `54 passed in 3.15s`。四份受版本控制的 `aurauv.pyz` 与一次
独立 `/tmp` 构建哈希一致，均输出 `aurauv 0.1.1`。

## 2. 明确保留的既有行为与非目标

以下内容没有被重组或改写：

- uv 仍唯一负责依赖解析、lock、Python 安装与环境同步；
- 原 `pytorch` provider 的 CPU/MPS/CUDA 检测、官方 index 合同、machine
  fingerprint、preflight、fallback 和 runtime 检查未改；
- `sync` 的 route extras、workspace owner、共享 `.venv`、member standalone lock
  主合同未改；
- `add/remove` 仍先执行原生 uv metadata mutation，再进行 routed sync；
- 正常无只读参数的 provider repair、显式授权 fallback、state 写入能力保留；
- 没有把 accelerator profile 扩成 Triton、GUI/headless、ROCm、XPU 的交叉积；
- 未来 `xxx-package` / `xxx-package-headless` 或 Triton 仍应使用独立 provider，
  通常使用独立 route；
- 本轮没有修复 uv 参数表漂移，只在 README 声明；
- 没有修改 Cyranyx 或其他消费项目的 `pyproject.toml`、lock、`.venv` 或 state；
- 没有修改 `setup.py`、`setup.sh`、`setup.bat`、`bootstrap/aurauv.py`、
  `bootstrap/aurauv.sh`、`bootstrap/aurauv.bat` 的启动逻辑；这些入口通过测试确认
  能继续委托给更新后的 `pyz`。

因此，本次变更不是依赖管理器重写，也不是路由架构重组。

## 3. 主要逻辑修改

### 3.1 命令日志脱敏

`CommandRunner` 现在维护两份 argv 视图：

- execution argv：原值不变，实际传给 `subprocess.run`；
- display argv：只用于 INFO 日志与异常，由脱敏函数生成。

覆盖范围：

- 分离参数：`--token SECRET`、`--password SECRET` 等；
- 内联参数：`--token=SECRET` 等；
- URL userinfo：`https://user:password@example.invalid/...`；
- URL 敏感查询参数：`token`、`signature`、`api-key`、`credential`、
  `password` 等；
- subprocess 捕获后进入 `CommandError` 的 stdout/stderr 中，由本次命令参数派生
  的 secret 和 URL 凭据。

空 secret 不会作为空字符串替换整段诊断。该层不改变 uv 收到的实参，也不记录或
持久化 secret。

### 3.2 Provider package-family closure

新增配置形态：

```toml
[tool.aurauv.routes.accelerator]
detector = "pytorch"
providers = ["pytorch", "pytorch-companions"]

[tool.aurauv.providers.pytorch-companions]
type = "pytorch-companion"
project = "."
route = "accelerator"
base-provider = "pytorch"
packages = ["torchaudio", "torchcodec"]
imports = { torchaudio = "torchaudio", torchcodec = "torchcodec" }
```

合同约束：

- companion 必须属于 environment owner，因为它观察共享 managed interpreter；
- base provider 必须是同 route 的 `pytorch` provider；
- base provider 必须在 route 的有序 `providers` 列表中先于 companion；
- `packages` 必须非空、归一化后唯一；
- `imports` 必须精确覆盖 `packages`；
- companion package 不得与 base provider 的核心 package 重叠；
- 所有 provider 必须恰好挂接到其声明的 route，route 内禁止重复成员。

激活模型是 `installed-after-sync`，不是 raw lock membership。原因是一个 `uv.lock`
可同时保存不同 marker、platform 与 extra 分支；直接读取“lock 中出现过”会把未被
uv 选中的分支误判为当前环境。Aurauv 让 uv 完成解析/同步，再从 managed
interpreter 的实际 distributions 得到活动集合。

每个 configured companion 的结果为：

| 实际状态 | Provider 行为 |
|---|---|
| 未安装 | 记录在 `inactive_packages`，no-op，不导致失败 |
| 已安装且可导入 | 记录 distribution version、module version 与可识别 backend |
| 已安装但不可导入 | repairable verification failure |
| module version 显示 backend 且与 Torch route 不同 | repairable verification failure |
| CUDA route 但 `torch.version.cuda` 不存在 | verification failure |

成功写入的 state 在 `provider_results.pytorch-companions` 下包含：

- `activation`；
- `configured_packages`；
- `active_packages` / `inactive_packages`；
- `distributions`；
- `module_versions` / `module_backends`；
- `torch_cuda_version` / `expected_backend`；
- `backend_mismatches`。

Provider runtime verification 改为严格按 `route.providers` 顺序运行。因而基础 Torch
验证总在 companion 前完成，state 也保留相同的因果顺序。

### 3.3 未来 `torchaudio` / `torchcodec` 行为

Aurauv 0.1.1 不会无条件安装 `torchaudio` 或 `torchcodec`，也不会自行发明版本约束
或 package source。uv 继续依据消费项目的 `pyproject.toml` 与 `uv.lock` 决定是否
安装以及安装哪个 wheel。

消费项目只有显式添加上面的 route-attached companion 配置后，才启用闭环。模板
与示例已更新；现有 Cyranyx 配置没有在本仓库任务中被自动改写。

启用后，典型行为如下：

| 调用与环境 | Aurauv 行为 |
|---|---|
| companion 未安装 | 验证成功，state 明确标为 inactive |
| companion 与 Torch 可导入且 backend 一致 | 验证成功，证据进入 state |
| 普通 `sync` 后 `torchaudio` 不可导入 | 对实际 active companion 做最多一次 routed focused reinstall，然后复验 |
| 普通 `add/remove` 后不兼容 | focused reinstall/复验仍失败时，事务恢复 metadata/lock；原 root lock 存在时补偿恢复环境；不写新 state |
| `--check` / `--locked` / `--frozen` 下不兼容 | 直接报告验证失败，不做 Aurauv repair/fallback resync，不写 state |
| `add/remove --no-sync` | 尊重 uv 的 no-sync；本次调用不做 routed sync、provider verify 或 state 写入 |

以原问题“PyTorch CUDA 13.2、TorchAudio CUDA 13.0”为例：TorchAudio import 或
backend evidence 会使 companion verification 失败。普通可变 sync 可尝试一次只针对
活动 companion 的 reinstall；若原 lock/source 仍只能提供不兼容 wheel，Aurauv 会
保持失败并拒绝写成功 state，而不是在 lock 外用 pip 覆盖。最终版本/source 兼容性
仍必须在项目 TOML/lock 中由 uv 可解析地表达。

### 3.4 Read-only capability model

Aurauv 新增六项内部能力：

- uv self-update；
- Python install；
- member lock refresh；
- provider focused repair；
- runtime fallback resync；
- state write。

`--check`、`--dry-run`、`--locked`、`--frozen` 任一存在时，这六项全部关闭。参数仍
原样交给 uv；Aurauv 不重新定义 uv 的 lock/environment 语义。

本机核对版本为 `uv 0.12.5 (x86_64-unknown-linux-gnu)`。其 help 定义：

- `--locked`：断言 `uv.lock` 保持不变；
- `--frozen`：同步时不更新 `uv.lock`；
- `--dry-run`：不写 lock、不修改环境；
- `--check`：检查环境是否与项目同步。

所以 `--locked` / `--frozen` 不是“整个进程不修改环境”。本次只保证 Aurauv 自身
不追加 repair、fallback resync、member refresh、state/update/install 等副作用。

### 3.5 参数行为：Aurauv 与 uv 的区别

| 调用 | uv 原生部分 | Aurauv 0.1.1 附加行为 |
|---|---|---|
| `sync` | 解析/同步 lock 与环境 | 选择 machine route、检查 member lock、注入 owner project/extras、provider/import 验证、必要时一次 repair/经授权 fallback、成功后写 state |
| `sync --check` | 检查环境同步状态 | route/preflight 与 runtime verify 保留；member 只检查；无 update/install/repair/resync/state |
| `sync --dry-run` | 不写 lock、不修改环境 | route/preflight 保留，member 只检查；uv 返回后不做 runtime verify/state；无 update/install/repair/resync |
| `sync --locked` | lock 必须保持不变，但可同步环境 | route 注入与 verify 保留；禁止 Aurauv update/install/member refresh/repair/resync/state |
| `sync --frozen` | 不更新 lock，但可同步环境 | 与上一行相同的 Aurauv capability 限制 |
| `--offline` | 禁用 uv 网络访问 | 不是只读开关；正常 route/verify/repair/state 能力保留，member 与事务补偿同步携带 offline。uv/Python 的独立授权策略仍适用，缺少缓存时操作会失败 |
| `add/remove` | 修改项目依赖 metadata/lock | Aurauv强制第一阶段 `--no-sync`，再 member reconcile、routed root sync、verify/state；全流程受事务保护 |
| `add/remove --no-sync` | 只做 uv 原生 mutation | 不追加 routed sync/verify/state；仍 checkpoint 并在失败时恢复已知 metadata |
| `run` | 同步后执行子程序 | Aurauv先做 routed inexact sync/verify/state，再以 `uv run --no-sync` 执行，避免第二次未路由 sync |
| `run --no-sync` | 不同步后执行 | 不做 Aurauv pre-sync/repair/resync/state，但仍验证当前 provider 状态 |
| `--aura-no-route ...` | uv 原生命令 | 直接 passthrough；不承诺保留 route，不进入上述 managed transaction |

只读 capability 识别 `uv run` 时使用 run option view，不主动把已识别的 child
arguments 当作 Aurauv 参数。已知 parser 参数漂移仍见第 9 节。

### 3.6 `add/remove` 事务恢复

在第一条 mutation 命令执行前，`MetadataTransaction` 以内存 bytes + file mode
checkpoint 以下精确路径：

- environment owner 的 `pyproject.toml`、`uv.lock`；
- invocation root 的上述文件；
- uv workspace members 的上述文件；
- `[tool.aurauv.members]` 配置成员的上述文件；
- 当前环境对应的 state 文件。

失败恢复规则：

1. 以同目录临时文件、`fsync`、`os.replace` 原子恢复原内容与 mode；
2. 删除本事务新建而事务前不存在的 checkpoint 文件；
3. 不创建持久 `.bak`、`.old` 或 `.venv` 副本；
4. 若 routed sync 可能已改变环境且事务前存在 root lock，恢复 metadata 后执行带
   原 route extras 的 `uv sync --locked`；
5. 若事务前没有 root lock，或补偿 sync 失败，明确报告无法证明环境恢复，并删除
   无法再证明对应当前环境的 restored state；
6. `--offline` 会传给补偿 sync；
7. uv 原生命令返回非零与后续 provider/import/state 失败都走同一事务边界。

事务不尝试复制 `.venv`，也不支持命令期间并发手工编辑同一 metadata 文件。没有
旧 root lock 时，旧环境不可重建是明确边界，不会通过猜测 resolver 结果掩盖。

## 8. 风险与边界

1. Companion provider 是显式项目合同；未配置的旧项目不会自动获得 companion
   验证。要在 Cyranyx 启用，需要单独修改其 environment-owner TOML 并由 uv 更新
   lock；该项目不在本次写入范围。
2. Companion 负责发现和拒绝不兼容，不在 lock 外强装版本。若 lock/source 本身
   没有兼容 wheel，操作仍会明确失败。
3. Backend tag 只在 module version 明确携带 `+cuNNN`、`+cpu` 或 ROCm 标记时比较；
   没有 tag 的包仍依赖实际 import 成功与基础 Torch provider 证据。
4. Transaction 不复制 `.venv`。有旧 root lock 时用 uv 补偿；无旧 lock 时无法证明
   恢复旧环境，必须由用户审阅后再 routed sync。
5. Metadata transaction 假定执行期间没有外部进程并发编辑相同文件。
6. Windows BAT 原生执行仍需 Windows CI 或 Windows 主机；本轮在 Ubuntu 只验证
   可确定的静态合同。

## 9. 本轮未修的 uv 0.12.5 参数漂移

遵照任务要求，本轮只在 README 声明，没有修改 parser/copy table：

- `uv run` child arguments 中与 uv option 同名的 `--isolated`、`--no-project`、
  `--script`、`--gui-script` 仍可能发生边界误判；
- `uv add --optional NAME PACKAGE` 的 follow-up sync 不会自动变成
  `sync --extra NAME`；
- follow-up sync 尚未完整复制 `--no-editable-package`、
  `--no-install-project`、`--no-install-workspace`、`--no-install-local`、
  `--no-install-package`、`--upgrade-group`、`--prerelease-package`、
  `--system-certs` 与项目型 `--script`。

要求这些参数精确原生语义时，README 建议使用 `--aura-no-route` 直通，再由调用者
执行审阅过的 routed sync；直通不等于 route 已保留。

+"""In-memory metadata checkpoints for multi-stage project mutations."""
+
+from __future__ import annotations
+
+import os
+import stat
+import tempfile
+from collections.abc import Iterable
+from dataclasses import dataclass
+from pathlib import Path
+
+from .errors import AurauvError
+
+
+@dataclass(frozen=True, slots=True)
+class FileCheckpoint:
+    path: Path
+    content: bytes | None
+    mode: int | None
+
+
+class MetadataTransaction:
+    """Restore an exact set of small metadata files without persistent backups."""
+
+    def __init__(self, paths: Iterable[Path]) -> None:
+        unique = tuple(dict.fromkeys(path.absolute() for path in paths))
+        checkpoints: list[FileCheckpoint] = []
+        for path in unique:
+            if path.is_symlink():
+                raise AurauvError(
+                    f"Transactional metadata must not be a symlink: {path}"
+                )
+            if path.exists() and not path.is_file():
+                raise AurauvError(
+                    f"Transactional metadata must be a regular file: {path}"
+                )
+            checkpoints.append(
+                FileCheckpoint(
+                    path=path,
+                    content=path.read_bytes() if path.is_file() else None,
+                    mode=stat.S_IMODE(path.stat().st_mode) if path.is_file() else None,
+                )
+            )
+        self._checkpoints = tuple(checkpoints)
+        self._committed = False
+
+    def existed(self, path: Path) -> bool:
+        absolute = path.absolute()
+        return any(
+            checkpoint.path == absolute and checkpoint.content is not None
+            for checkpoint in self._checkpoints
+        )
+
+    @staticmethod
+    def _replace(path: Path, content: bytes, mode: int) -> None:
+        if not path.parent.is_dir():
+            raise AurauvError(
+                f"Cannot restore transactional metadata because its parent is missing: {path}"
+            )
+        descriptor, temporary_name = tempfile.mkstemp(
+            dir=path.parent,
+            prefix=f".{path.name}.",
+            suffix=".aurauv-restore",
+        )
+        temporary = Path(temporary_name)
+        try:
+            with os.fdopen(descriptor, "wb") as file:
+                file.write(content)
+                file.flush()
+                os.fsync(file.fileno())
+            os.chmod(temporary, mode)
+            os.replace(temporary, path)
+        finally:
+            temporary.unlink(missing_ok=True)
+
+    def rollback(self) -> tuple[Path, ...]:
+        if self._committed:
+            raise AurauvError("Cannot roll back a committed metadata transaction.")
+        restored: list[Path] = []
+        failures: list[str] = []
+        for checkpoint in self._checkpoints:
+            path = checkpoint.path
+            try:
+                if checkpoint.content is None:
+                    if path.exists() or path.is_symlink():
+                        if not path.is_file() and not path.is_symlink():
+                            raise AurauvError(
+                                f"Refusing to remove non-file transaction output: {path}"
+                            )
+                        path.unlink()
+                        restored.append(path)
+                    continue
+                current = path.read_bytes() if path.is_file() else None
+                current_mode = (
+                    stat.S_IMODE(path.stat().st_mode) if path.is_file() else None
+                )
+                if current == checkpoint.content and current_mode == checkpoint.mode:
+                    continue
+                assert checkpoint.mode is not None
+                self._replace(path, checkpoint.content, checkpoint.mode)
+                restored.append(path)
+            except (OSError, AurauvError) as exc:
+                failures.append(f"{path}: {exc}")
+        if failures:
+            raise AurauvError(
+                "Could not fully restore mutation metadata:\n" + "\n".join(failures)
+            )
+        return tuple(restored)
+
+    def commit(self) -> None:
+        self._committed = True
