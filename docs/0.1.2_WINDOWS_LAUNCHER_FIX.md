# Aurauv 0.1.2 Windows launcher 修复与验证

日期：2026-08-24
状态：已写入 `master` 工作树，未提交、未推送

## 1. 结论

0.1.2 只修复 Windows BAT 启动器的 Python 版本检测，并增加对应发行物回归约束。
`sync`、`add/remove`、machine routing、PyTorch/CUDA provider、companion package
family、事务恢复、只读能力模型、uv 参数转发、Python/SH launcher 业务逻辑均未改变。

Windows 原生测试已经证明：0.1.1 BAT 会把版本比较中的字面量 `^` 传入 Python，
导致兼容的 Python 3.14.7 被误判为不可用；删除双引号内错误的 `^` 后，portable
与 deployment BAT 均正常输出 `aurauv 0.1.1`。正式源码吸收该修复后版本提升为
0.1.2，并重建所有受版本控制的 pyz。

## 2. 根因与最小修复

错误表达式：

```bat
python -c "import sys; raise SystemExit(sys.version_info ^< (3, 11))"
```

该 Python 程序已经位于 CMD 双引号中。此处 `^` 不会作为必要的 CMD 转义被移除，
而会进入 Python 源码，使版本探测命令失败。launcher 随后把这个语法失败当作
“解释器版本不兼容”，最终错误报告没有可用的 Python 3.11+。

修复表达式：

```bat
python -c "import sys; raise SystemExit(sys.version_info < (3, 11))"
```

三条解释器候选路径使用同一修复：

1. `AURAUV_BOOTSTRAP_PYTHON`；
2. Windows Python launcher `py -3`；
3. `python` on `PATH`。

错误提示中的 `^>=` 没有修改。该表达式位于双引号外，必须保护 `>`，避免 CMD
把它解释成输出重定向。这一区别由 Windows 实测和最终 diff 同时保留。

## 4. Windows 原生证据

测试环境：

```text
Windows 11 amd64
uv 0.12.5
CPython 3.14.7
Aurauv 0.1.1 测试包
```

修复前观察：

- wheel 通过 `uv tool install` 安装成功；
- `aurauv aura version` 输出 `aurauv 0.1.1`；
- `portable/aurauv.bat aura version` 误报缺少 Python 3.11+；
- 直接运行 `python portable/aurauv.pyz aura version` 成功；
- `deployment/setup.bat aura version` 同样误报；
- Windows 没有 `py` launcher，但 `python` 明确存在于 `PATH`。

这组对照把故障定位到 BAT 的 `python -c` 版本检测，而不是 pyz、wheel、PATH 或
Python 安装本身。

在测试副本中只删除双引号内的 `^` 后：

- `portable/aurauv.bat aura version` 成功；
- `python portable/aurauv.pyz aura version` 成功；
- `deployment/setup.bat aura version` 成功；
- `sync`、`sync --locked`、`sync --frozen`、`sync --check` 全部成功；
- `--check` 明确输出 `Would make no changes`。

Shared 中的修复前后文件与主仓库最终 BAT 逐字节比较成功。测试产生的 `.venv`、
`.aurauv` 和 outcome 日志只作为外部验收证据，没有复制进主仓库或发行物。

## 6. 不变行为

本轮没有改变：

- `sync` 的 Torch/CUDA/machine routing；
- `add/remove` 的 routed follow-up sync 与事务恢复；
- provider package-family closure；
- `torchaudio`、`torchcodec` companion verification/state；
- 未来 Triton、GUI/headless、ROCm、XPU 的 provider/route 扩展边界；
- `--locked`、`--frozen`、`--check`、`--dry-run` 的副作用模型；
- uv 参数透传与 README 已声明的 uv 0.12.5 参数漂移；
- Python 与 SH launcher 的任何业务逻辑；
- Colab 路径。

Aurauv 与 uv 的参数语义差异仍以 README 和 0.1.1 主报告为准；0.1.2 没有新增或
删除任何 CLI 参数。

## 7. 剩余边界

Windows 原生测试实际命中 `python` on `PATH` 分支。以下分支通过相同代码和静态
回归约束覆盖，但尚未逐一获得 Windows 原生运行证据：

- 显式 `AURAUV_BOOTSTRAP_PYTHON`；
- `py -3`；
- Python 低于 3.11 时的拒绝；
- uv 缺失时的零修改退出；
- 路径含特殊 CMD 字符的解释器。

这些分支适合后续加入 Windows CI。当前修复不应扩展为 launcher 重写或新的 Python
发现机制。
